# ContextTree MCP 🌳

**Глубокий семантический поиск по коду для ИИ-ассистентов — на основе AST-парсинга и локальных эмбеддингов. 100% офлайн.**

[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)
[![MCP](https://img.shields.io/badge/protocol-Model%20Context%20Protocol-purple.svg)](https://modelcontextprotocol.io)
[![README (EN)](https://img.shields.io/badge/README-English-blue.svg)](README.md)

ContextTree MCP — локальный [Model Context Protocol](https://modelcontextprotocol.io)-сервер,
который даёт ИИ-ассистенту **структурное понимание** кодовой базы. Он объединяет два мира:

- **tree-sitter** парсит исходники в AST и извлекает *логические блоки* — функции, методы, сигнатуры классов с докстрингами.
- **sentence-transformers** (`all-MiniLM-L6-v2`) векторизует каждый блок — обогащённый путём к файлу, именем класса, именем метода и докстрингом — и складывает в локальное векторное хранилище **ChromaDB**.

Результат: ваш ассистент находит код по *смыслу*, а не по ключевым словам, и каждый результат приходит с точным путём к файлу и номерами строк.

> 🔒 **Приватность прежде всего.** Всё работает на вашей машине: парсинг, модель эмбеддингов, векторный индекс. Никаких облачных вызовов, никакой телеметрии — код не покидает диск, на котором лежит.

## Почему не обычный текстовый поиск?

`grep` и полнотекстовый поиск сопоставляют строки. Они ломаются именно там, где разработчику нужна помощь:

| Задача | Текстовый поиск | ContextTree MCP |
|---|---|---|
| *«Где мы валидируем JWT-токены?»* | ❌ нужно угадать точное ключевое слово | ✅ найдёт `AuthService.verify_token()`, даже если слова «валидация» в коде нет |
| Найти метод после рефакторинга имени | ❌ сломан переименованием | ✅ докстринг + контекст сохраняют смысл |
| Отличить определение от использования | ❌ невозможна без regex-акробатики | ✅ AST-уровень разделяет объявления и места вызова |
| Вернуть точные координаты | ⚠️ только строка совпадения | ✅ метаданные `file`, `class`, `method`, `start_line`, `end_line` |
| Игнорировать шум комментариев / строк / импортов | ❌ | ✅ индексируются только реальные логические единицы |

## Возможности

- 🌲 **AST-чанкинг** — индексируются функции, методы и сигнатуры классов через tree-sitter, а не произвольные текстовые окна.
- 🧩 **Context-Enriched Logical Blocks** — каждый документ несёт путь к файлу, класс, имя метода, докстринг и тело: запрос «логика повторных попыток оплаты» попадает в нужный метод.
- ⚡ **Инкрементальная индексация** — SHA-256-хэш каждого файла; обрабатываются только новые / изменённые / удалённые файлы.
- 🔍 **Семантический поиск** — запрос на естественном языке → ранжированные фрагменты кода с точными диапазонами строк.
- 📞 **AST-поиск использований** — реальные места вызова любой функции или класса, без ложных срабатываний на строковых литералах и комментариях.
- 🗄️ **Локальный персистентный индекс** — ChromaDB хранится в `.chroma/`, переживает перезапуски и никогда не попадает в Git.
- 🔌 **Stdio-транспорт MCP** — подключается к Claude Desktop, OpenCode, Cursor, Cline или любому MCP-совместимому клиенту.

## Установка

Требуется Python **3.12+**. В качестве быстрого современного пакетного менеджера рекомендуется [`uv`](https://docs.astral.sh/uv/):

```bash
git clone https://github.com/<your-org>/mcp-context-tree.git
cd mcp-context-tree

# Вариант A — uv (рекомендуется): резолвит зависимости из pyproject.toml, создаёт uv.lock
uv sync

# Вариант B — классический pip + venv
python -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

> 💡 При первом запуске скачивается модель эмбеддингов (~90 МБ). PyTorch ставится как зависимость `sentence-transformers`; достаточно CPU-сборки — GPU не требуется.

### Регистрация в MCP-клиенте

Пример конфигурации (Claude Desktop / любой клиент со stdio-серверами):

```json
{
  "mcpServers": {
    "context-tree": {
      "command": "<path-to-venv>/bin/python",
      "args": ["-m", "context_tree"],
      "env": {}
    }
  }
}
```

*(В Windows используйте `<path-to-venv>\Scripts\python.exe`.)*

## Инструменты ассистента

| Инструмент | Сигнатура | Описание |
|---|---|---|
| `index_workspace` | `(directory_path: str)` | Обходит проект, по хэшам находит изменённые файлы и инкрементально обновляет коллекцию ChromaDB. |
| `semantic_search` | `(query: str, limit: int = 5)` | Поиск на естественном языке по индексированному коду. Возвращает обогащённые сниппеты с `file`, `class`, `start_line`, `end_line`. |
| `find_ast_usages` | `(symbol_name: str)` | AST-поиск реальных мест вызова / инстанцирования функции или класса. |

Типичный сценарий:

```
1. index_workspace("D:/projects/my-app")
2. semantic_search("где обрабатываются повторные попытки оплаты", limit=8)
3. find_ast_usages("PaymentGateway.retry")
```
